# 00 总规则与执行协议

> 当前实现以 [13-当前版本基线与验收清单.md](13-当前版本基线与验收清单.md) 为准：首页为当前 MacCMS 视频源；直播入口暂时隐藏。文中上游 v1.3.6 信息仅作为历史设计参考。

## 1. 规则优先级

开发模型必须按以下优先级处理冲突：

1. 用户本轮明确要求。
2. `13-当前版本基线与验收清单.md` 中已确认的当前产品范围。
3. 本文档的安全、兼容和证据规则。
4. `01` 至 `10` 的模块规则。
5. `11` 的阶段任务顺序。
6. 上游主工程实现细节。

主工程是产品行为参考，不是旧 Android 技术实现模板。2026-10-07 用户明确要求扩展至 Android 4.1；当前技术最低边界为 API 16。凡是 Compose、Compose for TV、Media3、当前最新版 AndroidX 或高版本专属能力，与 API 16 冲突时必须改写，不得强行移植。具体改动见 [兼容扩展](17-Android4.1兼容扩展.md)。

## 2. 最高级硬约束

- 最低系统固定为 Android 4.1 / API 16，不得悄悄提高 `minSdk`。
- 本仓库已经是独立兼容版，包名为 `com.tvbox.android44`。允许修改这里的 `app/`，不得引入上游 Compose/Media3 模块。
- UI 使用 XML + 传统 Views；禁止使用 Jetpack Compose、Compose for TV。
- 播放器使用支持 API 16 的旧版 `com.google.android.exoplayer2`；禁止使用当前 Media3。
- 不得用 `tools:overrideLibrary`、反射吞错或关闭 Lint 来掩盖不兼容依赖。
- 不得关闭 HTTPS 证书校验、信任全部证书或允许任意主机名。
- 不得把 AI Key、签名口令、Cookie、私有源地址或用户输入写入 Git、日志和截图。
- 不得把平台直播的网页解析逻辑塞进盒子；客户端只调用 `platform_live_server` 的统一接口。
- 不得把无授权内容打包进 APK；影视、直播和 AI 服务必须由配置提供，并由使用者确认授权。
- 默认按 Gate 分阶段验证；用户授权的跨阶段补全可继续完成所有必要工作，并分别记录证据。需要设备或正式密钥的项保留为待验收。

## 3. 模型工作协议

开始修改前，模型必须输出：

- 本轮目标和明确非目标。
- 准备读取、创建和修改的文件清单。
- 对 API 19 有风险的依赖或系统 API。
- 可执行的验收命令与需要实机完成的步骤。

实施过程中，模型必须：

- 优先复用主工程的领域含义、解析规则和用户文案，不复制 Compose UI 代码。
- 保持改动小且可回滚，不在一个提交中同时改播放器、网络和全部页面。
- 网络、磁盘、JSON 解析和哈希计算全部离开主线程。
- 对 Activity/Fragment/请求/播放器生命周期做成对清理。
- 先处理第一个具体失败，不用大量兜底掩盖根因。
- 发现规则之间冲突时停止扩展范围，记录冲突和建议决定。

完成后，模型必须输出：

- 实际修改文件。
- 实际运行命令及结果摘要。
- API 19 已验证项、仅静态验证项、尚未验证项。
- 已知风险和回滚方式。
- `AI_DEV_LOG.md` 或项目既有主/分支开发日志中的一条变更记录。

## 4. 证据规则

以下内容不能作为“兼容完成”的充分证据：

- Gradle 同步成功。
- APK 构建成功但未安装。
- 高版本手机或模拟器能运行。
- Manifest 声明了 `minSdk=16`。
- 依赖清单声称支持旧系统。
- 播放器创建成功但没有真实出画和声音。

每个核心能力至少要有三层证据：

1. 静态证据：依赖、Manifest、Lint、API 检查无阻断。
2. 自动化证据：解析、缓存、排序、换线等纯逻辑测试通过。
3. 运行证据：API 16 实机或模拟器完成对应流程，并在 API 19+ 回归；媒体能力最终以实机为准。

## 5. 失败与降级规则

- 单个影视来源失败不得让整个搜索崩溃。
- 单条直播线路失败要尝试同频道下一线路；全部失败后显示错误并允许返回列表。
- 平台直播解析失败只影响当前房间，不清空已加载的平台和分类。
- AI 服务不可用时，点播、直播、历史和设置仍可使用。
- 首页直接加载当前 MacCMS 来源；分类表失败不阻断内容，内容失败提供重试和换接口提示。
- OTA 不可用时只提示检查失败，不影响应用启动。
- 语音识别服务不存在时回退为文字输入，不将其视为崩溃。

## 6. 文档和编码规则

- 导入的中文 Markdown 保留 UTF-8 BOM；Java、Gradle、XML、YAML、Python、Shell 使用 UTF-8 无 BOM，避免编译或解释器问题。JSON 读取兼容 BOM，发布清单生成器使用 UTF-8 无 BOM。所有文本回读检查 U+FFFD。
- 界面文案使用简体中文，错误提示要告诉用户“发生了什么”和“下一步能做什么”。
- 规则文档出现的外部地址是结构示例或当前基准，不等同于长期可用承诺。
- 代码中的常量、超时、缓存容量和并发数必须有单一来源，禁止在多个页面复制魔法数字。

## 7. 禁止提前宣称

在 API 19 实机完成冷启动、遥控器浏览、详情、HLS/MP4 播放、返回恢复前，禁止使用以下表述：

- “已完全适配 Android 4.4”。
- “兼容所有电视盒子”。
- “支持所有 m3u8 / H.265 / 4K”。
- “与主项目完全一致”。

正确表述应区分“已实现”“已构建”“已在 API 19 验证”“受硬件限制未承诺”。
