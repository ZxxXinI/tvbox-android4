# 11 分阶段实施任务单

> 当前实现以 [13-当前版本基线与验收清单.md](13-当前版本基线与验收清单.md) 为准：首页为当前 MacCMS 视频源；直播入口暂时隐藏。文中上游 v1.3.6 信息仅作为历史设计参考。

## 总原则

本页保留原始建设顺序。当前已有实现与待补项按 [14-文档规划复查与待补任务.md](14-文档规划复查与待补任务.md) 的阶段状态表追踪；分别记录实现、自动化和设备证据，不因类或页面已存在就标记整个 Gate 完成。

每次只完成一个 Gate。开发模型必须先提交本 Gate 的文件清单和验收方式，完成后生成 Gate 报告。任何 Gate 的阻断问题未解决，不得通过添加更多功能绕开。

## Gate 0：环境与 API 19 空壳

目标：建立独立工程，证明技术栈可以安装到 API 19。

- 创建独立包名、Gradle Wrapper、版本目录和 README。
- 固定 `minSdk=19`，传统 XML Activity，横屏深色空壳。
- 声明普通/电视启动入口和非必需触摸屏。
- 加入基础 AndroidX Views 依赖，不加播放器/网络/图片库。
- 构建、Lint、依赖树检查；API 19 模拟器安装、冷启动、返回退出。
- 建立 `AI_DEV_LOG.md`。

通过条件：API 19 成功安装启动；依赖树无 API 21+ 阻断；无 `tools:overrideLibrary`。

## Gate 1：遥控器导航与静态页面

目标：先解决最难返工的焦点框架。

- 首页、搜索、详情、历史、电视、直播、推荐、设置占位页。
- 顶部四入口、数字键 1/2/3/6、返回栈；4/5 及直播导航保持隐藏。
- RecyclerView 假数据海报网格、焦点样式、弹窗和焦点恢复。
- 正常/大/超大字体，默认/影院主题的基础结构。

通过条件：只用遥控器可遍历全部页面，无焦点丢失和不可返回页面；720p 无关键裁切。

## Gate 2：MacCMS 单来源点播

目标：打通“分类/搜索/详情/选集”的真实数据链路。

- HTTP、Gson DTO、领域模型和 Repository。
- 分类、列表、搜索、详情、播放串/HTML 解析和内容过滤。
- 当前来源选择与自定义 URL 校验先使用开发配置，不做扫码。
- 页面加载/空/错/重试状态。
- 纯逻辑单测和一个授权 MacCMS 来源实测。

通过条件：API 19 能浏览、中文搜索、打开详情并看到合法线路/选集；断网可恢复。

## Gate 3：API 19 点播播放器

目标：证明旧盒子真正可播放。

- ExoPlayer 2.19.1 core/HLS/UI。
- HLS 和 MP4、播放/暂停、seek、上/下一集、返回释放。
- FIT 比例、电视横屏、音频焦点、屏幕常亮。
- API 19 真机完成 H.264/AAC HLS 和 MP4。

通过条件：真机出画出声并连续播放 30 分钟；退出无残留声音；多次进入不泄漏。

## Gate 4：历史与播放管家

目标：完成稳定观影闭环。

- 历史保存/恢复/清空，最多 100 条。
- 线路健康记录、尝试去重、评分和手动换线。
- 连续/频繁/累计缓冲判断、seek 冷却、自动换线开关。
- 坏线和卡顿的可重复测试夹具。

通过条件：进度跨进程恢复；故意坏线自动切到同集下一线路；关闭自动换线时不擅自切换。

## Gate 5：多来源增量搜索与详情补线

目标：复现 v1.3.6 的核心加载体验。

- 最多 3 条并发，主来源优先，搜索 3 秒超时。
- 增量去重结果和完成进度。
- 主详情先显示，其他来源 4 秒超时渐进补线。
- 5/30 分钟缓存、2 分钟失败冷却、取消隔离。

通过条件：首个来源结果立即可见；慢源不阻断；详情线路追加不重置焦点/选择；并发测试证明上限为 3。

## Gate 6：当前视频源完整首页

目标：完善当前 MacCMS 来源首页，两套主题、三档字体和遥控器行为。

- 分类表与内容分别加载，根级“全部”显示当前源内容。
- 父/子分类与父分类“全部”聚合，部分子分类失败保留成功内容。
- 分页去重、失败重试、切源取消、重建后选择与焦点恢复。
- 点击来源卡片直接获取该来源详情；无需豆瓣首页。

通过条件：来源首页、分类聚合、分页失败重试和详情返回恢复均可操作。自动化与真机证据分别记录。

## Gate 7：电视直播（当前暂缓，入口保持隐藏）

目标：完成 IPTV 频道体验。

- 文本下载、分组/频道/线路解析与单测。
- 全屏播放器、列表、切台、切线、数字选台。
- 直播缓冲阈值、4 秒无进度看门狗和换线终止条件。

通过条件：API 19 真机真实频道播放；切台 20 次无崩溃；坏线不会无限循环。

## Gate 8：平台直播（当前暂缓，入口保持隐藏）

目标：接入现有服务端，不迁移平台抓取逻辑。

- 服务地址配置、sites/categories/rooms/resolve。
- 平台→父分类→子分类→房间→播放器导航。
- 最高画质候选、多 CDN、地址重取和强制刷新。
- 五平台按当时服务可用性逐一记录。

通过条件：至少一个可用平台完成真机播放；所有平台接口错误均不崩溃；Cookie 不存在 APK/日志。

## Gate 9：AI 推荐和扫码配置

目标：利用用户已有中国模型额度完成推荐能力。

- Chat Completions 兼容提供方、结构化提示和解析。
- 推荐页、快捷词、换一批、点击后普通搜索。
- 局域网一次性配置会话、二维码、AI 和自定义 MacCMS 表单。
- 语音识别存在则启用，不存在则文字降级。

通过条件：用户的实际模型配置完成成功推荐；错误 Key 不泄漏；配置弹窗关闭后端口释放。

## Gate 10：OTA、完整回归与发布

目标：形成可长期安装维护的交付包。

- 独立更新清单、版本比较、下载进度、大小/SHA-256。
- API 19 和 API 26+ 安装权限分支、FileProvider 和系统安装器。
- Release R8/签名、APK 哈希、更新说明。
- 当前点播版完成全设备矩阵和 30 分钟点播稳定性；60 分钟直播与切台验收仅在 Gate 7/8 恢复后执行。

通过条件：Release APK 在 API 19 和较新 Android 都能安装运行；错误哈希不可安装；发布材料齐全。

## 后续维护 Gate

- 依赖升级一次只升一个族，先核对 `minSdk` 再回归 API 19。
- 外部接口变化只修改 data/配置层，不让页面重写。
- 播放器安全或格式问题优先评估服务端转码/代理，不盲目引入不兼容新播放器。
- 每次发布保留 API 19 核心回归，不因设备老旧而只做静态检查。
