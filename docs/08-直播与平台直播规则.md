# 08 电视直播与平台直播规则

> 当前实现以 [13-当前版本基线与验收清单.md](13-当前版本基线与验收清单.md) 为准：首页为当前 MacCMS 视频源；直播入口暂时隐藏。文中上游 v1.3.6 信息仅作为历史设计参考。

## 1. 两类直播必须分离

电视直播和平台直播共享播放器基础设施，但数据来源和状态机不同：

- 电视直播：下载 IPTV 文本，解析固定频道和多条线路。
- 平台直播：浏览远程平台目录，由服务端实时解析房间临时流。

不得把两者 DTO、缓存 key 或换线规则混成一个巨大页面类。

## 2. IPTV 文本解析

当前主工程源码快照的默认 IPTV 地址为 `http://20.205.10.127:8787/tvbox/result.txt`。Android 4.4 版本必须把它作为可替换配置，而不是页面常量；该外部地址的授权、可达性和长期稳定性需在每次发布前重新确认。

逐行解析，规则如下：

1. trim，忽略空行。
2. 找第一个英文逗号，左侧为名称，右侧为来源。
3. `分组名,#genre#` 更新当前分组。
4. 没有当前分组时忽略频道行。
5. 频道来源按第一个 `$` 截断为真实 URL；只接受 `http/https`。
6. `$LR•IPV4•29『线路...』` 等元数据只作为线路名，不进入播放 URL。
7. 清理频道名前无意义编号和 HTML。
8. 同组同名频道合并，重复 URL 去重；不同组同名频道不合并。
9. 最终按出现顺序连续编号，从 1 开始。

解析器必须能处理 CRLF/LF、BOM、中文分组、畸形行、重复行和无分组旧格式。

## 3. 电视直播页面状态

- 加载频道、当前频道索引、当前线路索引、频道列表是否显示、数字输入缓冲、播放状态和错误。
- 初次进入选择上次频道或第一个频道；保存时按稳定名称/分组恢复，索引只作回退。
- 左右切频道、上下切线路均首尾循环。
- 手动切换会重置当前频道的自动恢复计数。
- 确认键显示列表后，焦点落在当前频道；关闭列表回到播放器根焦点。
- 数字输入在短延迟后提交；不存在的频道号显示提示，不改变当前频道。

## 4. 电视直播故障恢复

触发条件：播放器错误、播放结束、连续/频繁/累计缓冲或 4 秒无进度。

恢复顺序：

1. 标记当前线路本会话已失败。
2. 尝试当前频道下一条未尝试线路。
3. 全部线路失败后停止自动循环，显示“当前频道所有线路暂不可用”。
4. 用户手动重试时清空本次尝试集合。

自动恢复过程中不弹阻断对话框，只显示短暂状态；全部失败后提供返回频道列表。

## 5. 平台直播服务边界

Android 客户端不得直接抓斗鱼、虎牙、哔哩哔哩、抖音或快手网页。现有服务端负责：

- 平台签名、WBI、anti-code、a_bogus 等易变逻辑。
- Cookie 和服务端环境变量。
- 分类/房间获取和临时流解析。
- 多画质、多 CDN 候选整理。

客户端只接收标准 JSON 和流地址。服务端不代理视频流时，盒子直接向平台 CDN 拉流。

## 6. 平台浏览状态机

```text
Sites
  → ParentCategories(site)
  → Categories(site, parentId)
  → Rooms(site, categoryId, page)
  → Resolve(site, roomId)
  → Player(stream candidates)
```

- 平台列表为空时显示服务地址/服务状态错误，不显示假数据。
- 没有父分类的平台可直接展示子分类。
- 房间分页向下加载，新增数据按 `site + roomId` 去重并保持顺序。
- 返回键严格退一级：播放器 → 房间 → 子分类 → 父分类 → 平台 → 首页。
- 每一级保存滚动位置和焦点 ID。

## 7. 解析结果规则

解析成功必须满足：

- `live=true`。
- 至少一个合法 `http/https` 候选。
- 每个候选包含 CDN、protocol、URL；缺失名称可使用“默认”。
- headers 只保留播放器确实需要的白名单，例如 User-Agent、Referer、Origin。
- 客户端优先服务端已排序的最高画质，不自行猜测平台 rate 含义。

房间未开播、服务端超时、格式错误和无有效候选分别显示不同提示。

## 8. 服务地址配置

- `TVBOX_PLATFORM_LIVE_SERVICE_URL` 在构建时注入默认值，运行时允许受控覆盖。
- 主工程 README 记录的测试构建地址为 `http://20.205.10.127:8868`；它只代表当时构建快照，不得作为新项目永久服务承诺。
- 地址必须是盒子可访问的局域网或公网地址，禁止默认 `localhost`/`127.0.0.1`。
- 规范化时去除末尾 `/`，只接受 `http/https`。
- 公网优先 HTTPS；旧盒子 TLS 不兼容时应修服务端证书/代理，不关闭客户端校验。
- 配置页可提供“测试连接”，依次检查 `/v1/live/sites` 和一个轻量接口，不在测试时解析大量房间。

## 9. 性能和缓存

- 平台、分类短期缓存，房间列表按页缓存；临时流地址不做长期持久化。
- 离开房间页取消封面请求和下一页请求。
- 同一房间正在 resolve 时合并重复操作。
- 老盒子房间网格建议每行 4 至 5 张 16:9 卡片，封面按目标尺寸解码。
- 服务端失败时保留已加载列表，允许用户返回或重试。

## 10. 测试最低集合

- IPTV：分组、多线路、元数据、重复 URL、不同组同名、无分组、BOM、畸形 URL。
- 遥控：首尾频道循环、线路循环、数字选台、列表焦点恢复。
- 看门狗：4 秒无进度、正常前进、暂停不触发、切台后重置。
- 平台：五个平台站点显示、父子分类、分页、房间未开播、多个 CDN、强制刷新。
- 故障：服务端离线、500、超时、错误 JSON、空 streams、播放 URL 过期。
- 真实播放：至少一个 IPTV 频道和每个可用平台各一个房间；不可用平台必须记录外部原因。
