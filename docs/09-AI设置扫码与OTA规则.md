# 09 AI、设置、扫码与 OTA 规则

## 1. 设置模型

`AppSettings` 至少包含：

- 当前首页视频来源 ID。
- 自定义视频来源列表。
- 主题：默认/影院。
- 字体：正常/大/超大。
- AI 提供方 ID、模型名、API Key。
- 启动检查更新开关，默认开启。
- 播放管家自动换线开关，默认开启。
- 平台直播服务地址和 IPTV 地址可作为扩展配置。

每个字段都有安全默认值。读取到未知枚举值时回退默认，不让设置损坏导致启动崩溃。

## 2. AI 提供方

当前产品支持 OpenAI Chat Completions 兼容请求，提供方作为可配置数据，而不是在页面写多个分支：

| ID | 名称 | API Base 基线 | 默认模型基线 |
| --- | --- | --- | --- |
| `agnes` | Agnes | `https://apihub.agnes-ai.com/v1/chat/completions` | `agnes-2.5-flash` |
| `deepseek` | DeepSeek | `https://api.deepseek.com` | 当前配置值 |
| `siliconflow` | SiliconFlow | `https://api.siliconflow.cn/v1` | `Qwen/Qwen2.5-7B-Instruct` |
| `qwen` | Qwen | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` |

- Base URL 如果已以 `/chat/completions` 结尾则直接使用，否则追加该路径。
- 模型名和服务端支持可能变化，必须允许用户修改，不把快照当永久事实。
- 请求使用 `Authorization: Bearer ...`，日志中绝不输出该 Header。
- 当前 Key 为空时明确提示配置，不发送无意义请求。

## 3. AI 请求与响应

请求：

- system 指令要求推荐 6 至 8 部作品。
- `temperature=0.4`，`max_tokens=1200` 作为基线。
- `searchKeyword` 只包含片名，不带年份、季数和解释。
- 用户输入 trim 后不能为空，长度设置合理上限，避免遥控器误输入超长内容。
- 连接 30 秒、读取 45 秒、写入 20 秒为基线；页面离开可取消。

响应：

- 从 `choices[0].message.content` 读取文本。
- 容忍 JSON 外包裹代码块或少量说明，但最终必须解析为标题和条目列表。
- 最多保留 10 条合法结果；缺片名或搜索关键词的条目丢弃。
- 解析失败显示“AI 返回格式无法识别，请重试”，不显示完整原文。
- 点击推荐条目后进入普通多来源搜索，AI 不直接提供播放 URL。

## 4. 推荐页行为

- 支持文字输入、快捷推荐词和“换一批”。
- 语音入口可保留实现但必须可降级；API 19 没有运行时权限，API 23+ 动态申请麦克风权限。
- 系统无语音识别服务时显示文字输入提示，不引导安装未知应用。
- 加载中禁止重复提交；用户修改问题并重提时取消旧请求。
- AI 失败不影响已显示的上一批推荐，可在顶部显示非阻断错误。

## 5. 局域网扫码配置

电视不适合遥控器输入长 URL/Key，因此保留临时配置服务：

- AI 配置默认端口 9978，自定义视频接口默认端口 9979；端口占用时可选择临近空闲端口并在界面展示实际值。
- 绑定局域网可达地址，不绑定公网接口；只在配置弹窗打开时运行。
- 生成带随机一次性 token 的 URL 和二维码。
- 手机页面只收集本次必要字段，提交后验证并保存，成功后主动关闭会话。
- token 有短有效期、单次使用；失败次数过多时使会话失效。
- HTTP 响应设置 `Cache-Control: no-store`，页面不回显完整 API Key。
- 关闭弹窗、Activity 停止或超时后必须关闭 ServerSocket/线程。
- 不申请相机权限，电视只生成二维码，由手机扫码。

API 19 设备可能无法确定正确 Wi-Fi 地址。应枚举非 loopback、已启用的 IPv4 地址，排除移动热点/虚拟网卡的明显无效项；多地址时让用户选择或显示多个候选。

## 6. 自定义视频接口

- 表单字段：接口名称、MacCMS Base URL。
- 名称 trim 后不能为空；URL 只接受 `http/https`，规范化末尾 `/`。
- 保存前可用轻量 `ac=detail&pg=1` 测试，测试失败时允许用户取消，不默认保存明显非法接口。
- 自定义 ID 使用随机稳定值，不根据名称生成，避免重名覆盖。
- 新增后可设为当前首页来源；删除当前来源时回退默认内置来源。
- 不允许手机页面修改内置接口定义。

## 7. OTA 清单

当前主工程源码快照从 `https://raw.githubusercontent.com/ZxxXinI/tvbox/main/update.json` 检查更新。Android 4.4 独立包必须使用自己的更新清单和 APK，避免主应用与兼容版相互推送错误安装包。

JSON 字段：

```json
{
  "versionCode": 10306,
  "versionName": "1.3.6",
  "apkUrl": "https://example.com/TVBox.apk",
  "apkSha256": "...",
  "apkSize": 12345678,
  "force": false,
  "changelog": ["更新说明"]
}
```

- 仅当远端 `versionCode` 大于当前版本时提示。
- 读取 JSON 前去除可选 BOM，忽略未知字段，关键字段缺失则报告清单错误。
- 检查请求使用 `Cache-Control: no-cache` 和固定 User-Agent。
- 启动自动检查失败只静默记录或轻提示；用户手动检查失败才显示明确错误。
- `force` 为预留字段，未完整实现强制更新状态机前不得阻断用户使用。

## 8. 下载、校验与安装

1. 用户确认更新后检查网络和可用空间。
2. 下载到应用缓存的单个临时文件，显示真实进度；未知长度显示不确定进度。
3. 有 `apkSize` 时核对大小；有 `apkSha256` 时流式计算 SHA-256。
4. 校验失败立即禁止安装并删除本次明确临时 APK。
5. 通过 `FileProvider` 生成 content URI，授予临时读取权限并打开系统安装器。
6. API 26+ 在用户操作时检查“安装未知应用”权限；API 19 直接尝试系统安装器。

不得在应用首次启动时强制打开安装权限设置。下载过程不得记录包含鉴权参数的完整 APK URL。

## 9. 设置页焦点与安全

- 每个设置分区有标题、当前值和可聚焦操作。
- 开关使用确认键切换，并立即持久化；失败时回滚 UI。
- API Key 只显示“未配置”或掩码，不提供明文展示按钮。
- 清空线路统计、历史、自定义接口需要确认。
- 二维码弹窗关闭后焦点回“模型/API Key/添加接口”按钮。
- 设置改变主题/字体后保持当前滚动位置和焦点语义。

## 10. 验收

- 四种 AI 提供方至少验证请求构造；有可用额度的提供方完成真实成功响应。
- 错误 Key、限流、超时、空 choices、非 JSON content 均不崩溃。
- 手机与电视同局域网完成 AI 配置和自定义接口配置，会话结束后端口关闭。
- API 19 和 API 26+ 分别验证 OTA 安装分支。
- 错误 SHA-256 的 APK 绝不能调起安装器。
- Git 搜索确认仓库不含真实 Key、签名口令和平台 Cookie。
