# 04 数据模型与接口规则

> 当前实现以 [13-当前版本基线与验收清单.md](13-当前版本基线与验收清单.md) 为准：首页为当前 MacCMS 视频源；直播入口暂时隐藏。文中上游 v1.3.6 信息仅作为历史设计参考。

## 1. 领域模型必须独立

至少定义以下领域对象，字段语义与主工程保持一致：

- `Category(id, parentId, name)`
- `ApiLine(id, name, baseUrls)`
- `Movie(id, apiLineId, apiLineName, name, typeId, typeName, posterUrl, remarks, year, area, language, actor, director, duration, description, playSources)`
- `PlaySource(name, episodes, lineId, lineName, sourceName)`
- `PlayEpisode(title, url)`
- `PagedMovies(page, pageCount, total, apiLine, categories, movies)`
- `WatchHistoryItem(...)`
- `LiveChannel(number, groupName, name, lines)`、`LiveChannelLine(name, url)`
- 平台、父分类、子分类、房间、流候选、解析后播放流模型。
- `AppSettings`、`AppUpdate`、AI 推荐结果和线路健康模型。

DTO 不得直接进入 UI。所有外部字符串先 trim；数字解析失败使用安全默认值；关键 ID/URL 缺失时丢弃该条而不是让整页失败。

## 2. MacCMS 请求协议

基础接口为 MacCMS V10 JSON VOD，统一使用 `GET`：

| 目的 | 参数 |
| --- | --- |
| 分类和列表 | `ac=detail&pg={page}` |
| 分类列表 | 可从列表响应的 `class` 字段读取 |
| 分类影片 | `ac=detail&pg={page}&t={typeId}` |
| 搜索 | `ac=detail&pg={page}&wd={keyword}` |
| 最近更新 | `ac=detail&h={hours}` |
| 详情 | `ac=detail&ids={id}` |

规则：

- Base URL 必须以 `/` 结束后再交给 Retrofit；自定义地址保存时统一规范化。
- 参数必须 URL encode，中文搜索词不得手工字符串拼接。
- JSON 容忍未知字段、`null`、数字字符串和部分字段缺失。
- `vod_id`、`type_id` 无法转为整数时丢弃该影片。
- `vod_content`、演员、导演等字段执行 HTML 标签与常见实体清理。
- `vod_play_from` 与 `vod_play_url` 使用 `$$$` 对齐线路，用 `#` 分集，用第一个 `$` 分隔标题和 URL。
- URL 允许直接 URL、Markdown 圆括号 URL、方括号 URL；最终只接受明确可播放的 `http/https`。
- 空线路、空集、空 URL 不进入领域模型。

## 4. 片名规范化和去重

多来源结果的稳定去重键：

```text
normalizedName + "|" + normalizedYear
```

`normalizedName` 至少执行：

- trim、转小写。
- 删除普通空格、全角空格和常见分隔符。
- 统一中文/英文括号。
- 保留能区分作品的数字和季信息；不得把“第1季”和“第2季”错误合并。

同键冲突时：主来源优先；主来源缺字段可用替代来源补元数据，但播放线路按来源独立保留。不同来源同名线路必须生成稳定 `lineId`，建议包含 `apiLineId + sourceName`。

## 5. 分类和内容过滤

- 首页分类只使用当前主来源，不混合不同站点的分类 ID。
- 父子分类通过 `parentId` 关联，找不到父级的分类放入安全兜底组或隐藏。
- 过滤伦理、电影解说、演员资料、新闻资讯等当前产品不需要内容。
- 过滤规则作用于首页、搜索、历史和 AI 搜索结果，保持一致。
- 过滤应基于标准化后的片名、类型、备注等字段，必须有误伤回归测试。

## 6. 豆瓣热播历史模块（不接入当前首页）

- 当前基准接口：`https://m.douban.com/rexxar/api/v2/subject/recent_hot/tv`。
- 分页大小 20，按请求参数区分剧集/综艺等类别。
- 请求携带当前主工程验证过的 User-Agent、Referer 和 Origin；海报也携带合适 Referer。
- 成功缓存 20 分钟；失败状态缓存 6 分钟，防止连续打失败接口。
- 首次失败优先返回仍可用的旧缓存；没有缓存时回退 MacCMS 首页。
- 豆瓣条目不是播放资源。点击后用标题搜索当前主来源，选择最接近的结果再取详情。
- 豆瓣接口属于外部非正式依赖，不得将“当前可访问”写成 SLA。

## 7. 缓存规则

| 缓存 | TTL | 上限 | 存储 |
| --- | ---: | ---: | --- |
| 分类/列表/搜索 | 5 分钟 | 80 个键 | 内存 LRU |
| 主来源详情 | 30 分钟 | 60 个键 | 内存 LRU |
| 来源失败冷却 | 2 分钟 | 每来源 | 内存 |
| 豆瓣成功 | 20 分钟 | 按分类/分页 | SharedPreferences 或小文件 |
| 豆瓣失败 | 6 分钟 | 按分类/分页 | SharedPreferences 或小文件 |
| 观看历史 | 长期 | 100 条 | SharedPreferences/JSON |
| 播放健康 | 30 天 | 300 条 | SharedPreferences/JSON |

- 缓存键包含来源、页码、分类或关键词，不能跨来源误用。
- 进行中的相同请求应合并，避免页面重复进入导致双请求。
- 内存压力回调到来时主动清空非必要内存缓存和图片内存缓存。
- 播放 URL 可能短期失效，不作为长期缓存真值。

## 8. 平台直播接口模型

客户端只访问统一服务：

- `GET /v1/live/sites`
- `GET /v1/live/categories?site=...`
- `GET /v1/live/rooms?site=...&categoryId=...&page=...`
- `GET /v1/live/resolve?site=...&roomId=...&refresh=0|1`
- 兼容旧目录时可读 `GET /v1/live/catalog`

解析结果只接受 `http/https` 流地址。服务端返回的请求头按白名单传给播放器数据源；不得接受客户端覆盖 `Host`、Cookie 或证书策略。

## 9. 存储规则

- 设置使用独立 `SharedPreferences`，每个 key 有默认值和迁移规则。
- JSON 读取先去除可选 BOM；损坏时保留备份摘要并回退空列表，不让应用启动崩溃。
- 历史按更新时间倒序，同一 `apiLineId + movieId` 只保留一条。
- 保存进度需节流，例如每 10 至 15 秒及暂停/退出时保存，不可每帧写磁盘。
- API Key 仅存应用私有区，不导出、不备份；日志显示时只展示掩码。
- 清空历史、线路统计和自定义接口必须有确认对话框。
