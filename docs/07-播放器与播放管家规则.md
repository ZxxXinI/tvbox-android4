# 07 播放器与播放管家规则

> 当前实现以 [13-当前版本基线与验收清单.md](13-当前版本基线与验收清单.md) 为准：首页为当前 MacCMS 视频源；直播入口暂时隐藏。文中上游 v1.3.6 信息仅作为历史设计参考。

## 1. 播放器技术边界

- 使用 `com.google.android.exoplayer2` 2.19.1 的 `SimpleExoPlayer`/`ExoPlayer` 与 `PlayerView`，不使用 Media3 包名。
- 首版模块只引入 core、HLS、UI；没有明确需求不引入 DASH、SmoothStreaming、IMA、Cast。
- 播放器实例每个播放页面最多一个，Adapter 和列表卡片禁止创建播放器。
- 播放页离开时停止、移除监听、释放播放器和 Surface。

## 2. 媒体创建

- 根据 URL/path 和必要响应头创建数据源；URL 必须是 `http/https`。
- `.m3u8` 或服务端标记 HLS 时使用 HLS MediaSource；`.mp4` 等使用 Progressive MediaSource。
- URL 无扩展名时允许 ExoPlayer 推断，失败后只做一次受控类型回退。
- 平台直播返回的 Referer/User-Agent 等请求头使用白名单注入。
- 不全局把同一组 Header 发送到无关域名。

## 3. 点播播放流程

1. 接收影片、当前线路、当前集和历史进度。
2. 创建当前线路全部合法剧集的播放列表，定位目标集。
3. prepare 后自动播放；首帧前显示加载状态。
4. READY 后记录一次成功并开始历史节流。
5. 集数自然结束时自动下一集；最后一集结束后停留并提示。
6. 原生/自定义控制层变化要同步当前集、速度和历史。

上一集/下一集切换后必须同步：详情选集索引、当前标题、历史记录和播放尝试 ID。

## 4. 显示比例和方向

- `PlayerView` 使用 FIT，完整显示画面，不拉伸、不裁切。
- 按视频真实宽高和像素宽高比判断竖屏/横屏。
- 电视设备始终保持横屏；竖屏内容居中显示并保留黑边。
- 手机可按真实视频方向切换，退出播放器恢复应用默认横屏。
- API 19 获取不到可靠视频尺寸时保持横屏 FIT，不凭 URL 猜比例。

## 5. 播放控制

- 播放/暂停、进度条、当前位置、总时长、标题、上一集、下一集、倍速和换线均有可聚焦入口。
- 倍速建议固定序列：`0.5x → 0.75x → 1.0x → 1.25x → 1.5x → 2.0x → 0.5x`；直播不提供倍速。
- 快进/快退步长 10 秒，并限制在合法范围。
- 手动 seek 后进入 3 秒冷却，直到下一次 READY 前不做卡顿换线判断。
- 暂停状态和首屏正常短缓冲不记为卡顿。

## 6. 播放管家健康数据

每条线路健康 key 至少包含来源、影片和线路标识，记录：

- 最近成功时间、最近失败时间、最近慢缓冲时间。
- 成功次数、失败次数、慢缓冲次数。
- 冷却截止时间；播放器会话内维护当前尝试及 READY 成功去重。

健康记录保留 30 天、最多 300 条，读取和写入时顺便清理。一次播放尝试进入 READY 多次只记一次成功。

## 7. 卡顿判断基线

点播：

- 连续缓冲超过 5 秒：`ContinuousBuffer`。
- 60 秒窗口内短缓冲达到 3 次：`FrequentBuffer`。
- 60 秒窗口内累计缓冲超过 8 秒：`CumulativeBuffer`。
- seek 后 3 秒及暂停期间不判断。

电视直播：

- 连续缓冲超过 6 秒。
- 60 秒内短缓冲达到 3 次。
- 60 秒内累计缓冲超过 12 秒。
- 播放状态正常但位置连续 4 秒不前进。

所有时间常量集中定义并用可注入时钟测试，禁止依赖测试中的真实 sleep。

## 8. 自动换线规则

- 自动换线开关默认开启。
- 播放错误或慢缓冲时先记录当前线路问题，再寻找同一集的下一条可用线路。
- 候选线路优先近期成功、避开 30 分钟冷却的失败线路，并轻度参考长期成功率。
- 不能循环回刚失败线路；一次播放会话记录已尝试候选。
- 切线尽量保持当前播放位置；新线路时长差异大或 seek 失败时从可播放位置开始并提示。
- 自动换线关闭时只显示错误和“手动换线”，不得擅自改变线路。
- 所有线路用尽后显示最终错误，提供重试当前、返回详情和手动选线。

## 9. 平台直播恢复

- 当前 CDN 失败时，先按服务端返回的候选列表切到下一 CDN。
- 当前临时地址可重取两次，每次设置退避，避免瞬间循环。
- 所有候选失效后调用 `resolve(..., refresh=1)` 获取新地址。
- 恢复期间保留房间信息并显示短提示，不退回平台首页。
- 页面离开后取消恢复任务，旧回调不得重新启动播放器。

## 10. 音频、系统与生命周期

- 播放前请求音频焦点；永久丢失时暂停，短暂丢失时按策略暂停或 duck。
- 收到 AUDIO_BECOMING_NOISY 时暂停点播。
- `onPause/onStop` 保存进度并暂停；进入后台不继续无提示播放视频。
- 播放时保持屏幕常亮，离开时恢复。
- 处理 HDMI 切换、Surface 重建和 Activity 重建，不因旋转/返回残留声音。

## 11. 播放器验收矩阵

至少记录以下真实结果：

| 项目 | API 19 实机 | 较新 Android 实机 |
| --- | --- | --- |
| H.264/AAC HLS 出画出声 | 必测 | 必测 |
| H.264/AAC MP4 出画出声 | 必测 | 必测 |
| 暂停/继续/seek | 必测 | 必测 |
| 上一集/下一集/自动下一集 | 必测 | 必测 |
| 返回详情和进度恢复 | 必测 | 必测 |
| 坏线自动换线 | 必测 | 必测 |
| 竖屏视频 FIT | 必测 | 必测 |
| H.265/4K | 只记录设备结果 | 只记录设备结果 |

失败报告必须包含：设备型号、Android 版本、CPU/ABI、媒体编码、分辨率、错误码和是否硬解，不包含私有播放 URL。

## 当前播放器接入补充（2026-10-06）

- 缓冲事件与 500 毫秒轮询检查阈值，READY 结束缓冲窗口；暂停取 playWhenReady，避免把 isPlaying=false 的缓冲误认为用户暂停。失败进入 IDLE 和自然结束清理窗口，避免额外触发缓冲换线。
- HealthStore 初始化、写入和清空都使用顺序磁盘队列，播放器读独立内存快照；成功落盘后才发布，失败保留旧值，清空结果异步回到设置页。
- 媒体类型依据 URL path，播放数据源观察实际 Content-Type，不额外探测。无扩展名由 Progressive 尝试；HLS MIME 或明确格式错误允许一次类型回退，HTTP 错误直接走换线/错误。
- 停止页面保存进度并释放播放器、音频焦点、广播和轮询；再进入恢复选集、进度与暂停意图。片尾进入下一集或最后一集停止时进度保持 0。
- PlayerFlowTest 使用受控 ExoPlayer 与假时钟验证上述 Activity 流程；VodMediaSourcesTest 验证类型策略，HealthStoreTest 验证存储。出画出声仍需物理盒子。
