## 本轮补全内容

- OTA 增加安装权限声明；清单严格校验哈希、版本、大小与布尔值；下载成功且校验通过后才产出可安装 APK。
- 下载流关闭后注销取消句柄；取消后的进度与完成回调不再更新页面。
- 分类子任务与父任务分开调度；共享请求各调用者独立取消；只有最后一个调用者取消才终止 HTTP。
- 首页、搜索、补线共用最多 3 个视频源 HTTP 请求，排队包含在超时预算内。
- 搜索主源晚到时在原位置更新卡片；按作品稳定 ID 更新点击目标和元数据，进度通知按完成顺序发送。
- 历史读取丢弃坏条目、排序、去重并返回独立快照；写失败保留原缓存，播放器写入离开主线程。
- 卡片显式可聚焦，主页面接入统一字体缩放，首页/搜索/历史/详情保存选择与焦点；页面销毁后丢弃晚到回调；后台数据不抢导航焦点。
- 首页分页仅在成功后递增；失败可重试，重复影片不再追加。
- 播放返回结果直接回传当前线路/集/进度，不等待磁盘；READY 结束缓冲计时，持续缓冲轮询，暂停/seek/开关及用尽线路保护。
- 历史按线路 ID/名称和集标题恢复，片尾清零；首次详情失败确认旧 URL；媒体响应头参与一次受控格式回退。
- 线路健康加载、写入、清空使用同一磁盘队列，写成功才发布快照，清空失败明确提示。
- 启动更新复用更新仓库，开关关闭或清单空时无请求，错误静默、重建去重；AI/扫码取消和过期回调隔离。
- 文案资源化与分类/选集/推荐列表差异更新；推荐重复条目去重并保持重排后的卡片焦点。
- 官方 Gradle/Maven 下载地址、Gradle 分发校验和、CI、正式签名强校验和发布材料生成器。

## 自动检查

需要 JDK 17、Android SDK platform 35、build-tools 34.0.0（AGP 默认）与 35.0.0。

```bash
bash gradlew testDebugUnitTest testReleaseUnitTest lintDebug lintRelease assembleDebug assembleRelease \
  --no-daemon --max-workers=4 --console=plain
```

- JVM 结果：`app/build/reports/tests/testDebugUnitTest/` 与 `testReleaseUnitTest/`。
- Lint：`app/build/reports/lint-results-debug.html` 与 `lint-results-release.html`。
- APK：`app/build/outputs/apk/debug/app-debug.apk` 与 `release/app-release.apk`。
- CI：`.github/workflows/android.yml`；push main、PR 或手动触发后上传 14 天保留的验证产物。未配置正式签名时 CI Release 是调试签名验证包，不会自动发布。
- Robolectric 4.10.3 仅在测试依赖中使用，保留 API 19 测试能力。模拟 Android API 的 JVM 测试不代表设备安装或解码验证。

当前实际结果见 [VERIFICATION_REPORT.md](../VERIFICATION_REPORT.md)。

上述复查中的 P1/P2 源码缺口已补齐，具体实现、回归与待设备验收项见 [14-文档规划复查与待补任务.md](14-文档规划复查与待补任务.md)。当前通过结果只覆盖云环境的静态与自动化验证。

## 正式签名与发布材料

配置可来自 Gradle 属性、环境变量或本地 `local.properties`，优先级依次为上述顺序。不要提交私钥和口令。

- `TVBOX_VERSION_CODE`：大于上一版的正整数；`TVBOX_VERSION_NAME`：新版本显示名。
- `TVBOX_STORE_FILE`、`TVBOX_STORE_PASSWORD`、`TVBOX_KEY_ALIAS`、`TVBOX_KEY_PASSWORD`：原发布签名；已有用户升级必须继续使用同一证书。
- `TVBOX_OTA_MANIFEST_URL`：本包自己的 HTTPS 清单地址。默认空时关闭在线检查。
- `TVBOX_REQUIRE_RELEASE_SIGNING=true`：正式构建必须启用；签名参数缺失时构建直接失败。

```bash
TVBOX_REQUIRE_RELEASE_SIGNING=true bash gradlew assembleRelease --no-daemon --console=plain
python3 scripts/prepare_release.py \
  --apk app/build/outputs/apk/release/app-release.apk \
  --apk-url https://YOUR-HOST/tvbox-android4/app-release.apk \
  --output-dir dist/release-validation \
  --changelog '本次更新说明'
```

脚本检查包名、当前 minSdk 16（也接受历史 19）、targetSdk 28、对应最低版本的有效 v1 签名；--previous-apk 额外检查版本码递增和证书连续性，显式签名迁移记录无法覆盖升级；从实际字节计算大小和 SHA-256，生成 APK 副本、`update.json`、`apk-info.json`、`signature.txt`、`SHA256SUMS`。默认拒绝调试证书；本地或 CI 验证可显式使用 `--allow-debug-signing`，生成材料会标注 `debug-validation-only`。

当前用户选择沿用 v0.0.1 的原调试证书，以保留覆盖升级。对此显式使用 `--allow-legacy-debug-upgrade` 并提供公开上一版 `--previous-apk`；工具必须验证同一调试证书且版本码递增，禁止签名迁移/验证模式混用，材料如实标注 `legacy-debug-release`。具体原证书摘要、命令与缺失私钥信息见 [发布记录](15-v0.0.2发布准备与记录.md)。

发布顺序：

1. 完成以下设备验收，确认 APK 使用原证书且版本号递增。
2. 用真实公开下载 URL 生成材料，复核证书摘要、版本、大小和哈希。
3. 上传 APK 后重新下载核对 SHA-256，确认 URL 实际返回完整 APK。
4. 最后更新本包的 `update.json`，记录回滚清单与上一版 APK。
5. 从上一版安装包执行一次 OTA 升级，确认数据与播放历史保留。

工具不会上传、创建 GitHub Release 或更新线上清单；`example.com` 和 `update.json.example` 都是结构示例。
