## 实现与文件用途

### 二维码、弹窗和名称

- `common/QrCode.java`：留白从 1 改为 4 模块，M 级纠错、纯黑白 RGB_565，像素不足时返回手动地址兜底；位图密度设为 DENSITY_NONE，避免隐式密度放大。
- `common/ui/QrImageView.java`：以最终测量像素生成，CENTER 显示，明确关闭过滤和抖动；尺寸受窗口宽度、320dp 上限及屏幕高度约束。首次焦点落到二维码，避免小屏先滚到关闭按钮。
- `res/layout/dialog_qr_config.xml`、`feature/settings/SettingsFragment.java`：两种配置共同使用新二维码视图，弹窗可滚动到关闭按钮，保留 URL、过期/手动地址提示和关闭后焦点恢复。
- `res/values/strings.xml`、`app/build.gradle`：桌面、应用品牌名称改为 TVBox4.1+，测试版本递增到 0.0.4/code4；包名、最低版本与证书保持兼容。

### 提供方与配置保存

- `data/local/SettingsRepository.java`：五家默认提供方按 DeepSeek、Qwen、GLM、KIMI、MIMO 排列。按提供方分别保存模型和 Key，首次升级将原完整配置迁到原提供方；保留 Agnes/SiliconFlow 的读取能力，不把密钥复制给其他提供方。
- 最终保存一次写入提供方、模型与 Key，推荐请求读取完整配置快照；获取列表不会调用保存方法。原视频源保存流程保持不扩展。
- `domain/model/AiProvider.java`：提供通用 Key 格式检查，避免换行/控制字符进入请求头；不会记录 Key。
- `data/remote/AiClient.java`、`data/repository/RecommendRepository.java`：MIMO 使用 api-key，其他默认提供方使用 Bearer，新默认提供方不强制 temperature=0.4；历史提供方保留旧行为。新提供方不自动跨地址重定向携带凭据。

### 手机网页与临时服务

- `feature/settings/AiConfigPage.java`：提供方选择、只读 API 地址、密码 Key 输入、获取按钮、明确选择模型、候选和高级手动输入。使用 ES5/XMLHttpRequest；不调用浏览器持久存储。
- 修改提供方会清空 Key；修改 Key 会清空列表和模型选择。网页使用请求代次忽略旧响应，查询中禁止重复点击，成功也不自动选择第一个型号。名称/消息以文本显示，供应商返回内容不会作为 HTML 执行。
- `feature/settings/ConfigHttpServer.java`：新增 POST /{token}/models（表单 provider/apiKey），返回 source/message/updatedAt/models[id,name]。AI 查询与最终 POST /{token} 保存分离；视频源模式不开放模型查询。
- 请求使用有限的两线程/八队列处理；新的模型查询取消旧查询。5 分钟到期、关闭及最终保存取消上游请求并释放所有客户端和监听端口。模型获取失败不会消耗一次性保存机会或既有失败计数。
- `data/remote/AiModelsClient.java`：统一网络栈，20 秒总预算，按五家端点请求；Qwen 兼容接口不支持时查询原生模型目录并处理分页。去重，依据模态和明确型号类型排除语音、图像生成、嵌入和重排项。
- 401/403 返回鉴权错误，不伪装成实时列表；不支持、网络/超时、空/坏响应可使用官方候选，明确标注更新时间及未验证本 Key 权限，也可手动输入。候选不是额度、权限或持续支持保证。
- Key 只在用户输入和请求中暂存，不进入 URL、日志、错误内容或页面初始回显；结果不保留上游原始错误体。关闭/过期取消请求，完成查询不提前落盘。

默认 Base：DeepSeek `https://api.deepseek.com`；Qwen `https://dashscope.aliyuncs.com/compatible-mode/v1`；GLM `https://open.bigmodel.cn/api/paas/v4`；KIMI `https://api.moonshot.cn/v1`；MIMO `https://api.xiaomimimo.com/v1`。均为普通中国区开放平台，非 Coding/Token Plan。

## 用户验收步骤（无需 ADB）

1. 手动安装上方测试 APK 覆盖旧版，确认桌面名称为 TVBox4.1+，原观看历史和视频源仍在。
2. 手机和投影连接同一局域网；设置 → 扫码配置 AI，用手机相机识别。检查留白完整、没有被窗口裁切；若仍不能识别，可在手机浏览器输入弹窗 URL，分别记录“相机识别”和“网页访问”的结果。
3. 手机网页选择提供方，确认只读地址，填写该家的普通 Key，点击获取列表。成功后自行选模型再保存；检查电视端提供方/模型更新且只显示 Key 掩码。保存后旧网址应失效。
4. 获取中切换提供方或修改 Key，确认旧结果不覆盖新选择；错误 Key 应提示鉴权错误，获取失败的候选应标明未验证。未点保存时电视端原配置不变。
5. 设置 → 扫码添加视频接口，识别第二个二维码；填写名称与合法 MacCMS URL、保存，确认接口列表可读取并选择。关闭后或 5 分钟后旧 URL 不能再提交。
6. 使用有权限的真实型号做一次影视推荐；再确认关闭弹窗后可以立即重新打开扫码，旧 Key 不会带到另一家，较新 Android 设备的既有功能正常。

本机没有连接投影设备。真实相机识别、局域网连通、各家有效 Key 下的列表及推荐，需要按上述步骤验收；没有把模拟数据或签名条件写成设备实测。
