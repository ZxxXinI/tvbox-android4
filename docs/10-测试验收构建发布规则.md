# 10 测试、验收、构建与发布规则

## 1. 验收原则

- 构建成功不等于运行成功，运行成功不等于 API 19 兼容成功。
- 每个 Gate 同时保留命令输出、设备信息和人工操作结果。
- 先验证核心路径，再验证异常路径；禁止只截图首页就宣称完成。
- 媒体、遥控器、TLS 和硬件解码以真实 Android 4.4 盒子为最终证据。

## 2. 自动化测试

### 2.1 纯逻辑单测

必须覆盖：

- MacCMS DTO 映射、HTML 清理、播放串解析。
- 内容过滤和片名规范化。
- 多来源并发上限、超时、增量合并、去重、取消和冷却。
- 详情线路追加和默认线路选择。
- 直播文本分组/合并/元数据清理。
- AI JSON/代码块解析和条目上限。
- 历史排序、覆盖、进度和上限。
- 播放管家评分、卡顿阈值、seek 冷却和尝试去重。
- OTA 版本比较、BOM、大小和 SHA-256。

### 2.2 Android 测试

- Activity 冷启动和导航返回。
- SharedPreferences 迁移/损坏回退。
- FileProvider URI 和安装 Intent。
- API 19/23/26 的权限分支。
- 关键页面焦点首次落点和弹窗焦点恢复。

UI 自动化可作为补充，不能替代真实遥控器人工回归。

## 3. 静态检查

每次 Gate 至少执行：

```powershell
.\gradlew.bat clean testDebugUnitTest lintDebug assembleDebug --console=plain
.\gradlew.bat :app:dependencies --configuration debugRuntimeClasspath
```

检查项：

- Manifest 合并结果的 `minSdk=19`。
- 依赖树不存在 Media3、Compose、OkHttp 4/5 或其他 API 21+ 库。
- Lint 的 `NewApi`、`InlinedApi`、网络安全和导出组件问题。
- APK 中 ABI、DEX 数量、资源大小和意外密钥字符串。
- Release R8 后反射使用的 Gson DTO/ExoPlayer 规则没有被误删。

如果启用 multidex，必须使用 API 19 兼容的 AndroidX Multidex 并在 Application 中正确安装；更优先通过减少依赖控制单 DEX。

## 4. 设备矩阵

最低矩阵：

| 设备 | 用途 |
| --- | --- |
| API 19 模拟器 | 安装、冷启动、页面、基础网络和崩溃筛查 |
| Android 4.4 真实盒子 | 遥控器、TLS、HLS/MP4、硬解、内存和长播 |
| API 23 或 Android 6 设备 | 中间版本权限和兼容回归 |
| API 26+ 电视/手机 | 未知来源安装、现代系统网络和权限回归 |
| 当前较新 Android 设备 | 防止只兼容旧系统而破坏新系统 |

每台设备记录：型号、Android 版本、API、ABI、内存、屏幕分辨率、遥控器型号和网络方式。

## 5. 核心手工用例

### 5.1 启动和点播

1. 全新安装冷启动，无历史/设置。
2. 首页热播成功；断网时缓存/回退可用。
3. 遥控器数字键进入搜索。
4. 中文搜索看到多来源增量结果和进度。
5. 打开详情时主线路先出现，后续线路追加不抢焦点。
6. 播放 HLS，暂停、seek、倍速、上一/下一集。
7. 返回详情再进入，进度和选集恢复。
8. 杀进程重开，从历史恢复。

### 5.2 故障与直播

1. 主视频接口超时，其他来源仍返回。
2. 当前播放 URL 故意失败，播放管家切换下一线路。
3. IPTV 多线路频道切台、切线、数字选台。
4. 直播卡顿/无进度后受控换线，不无限循环。
5. 平台直播完成平台→分类→房间→播放，临时地址过期后恢复。

### 5.3 设置、AI、OTA

1. 三档字体和两套主题均无裁切、焦点丢失。
2. 手机扫码配置自定义接口和 AI，端口会话结束后关闭。
3. AI 成功推荐；错误 Key 和超时可恢复。
4. OTA 无更新、有更新、错误哈希、权限拒绝、权限允许和安装器返回。

## 6. 性能验收

- API 19 盒子冷启动到可操作首页目标小于 5 秒；外部接口慢时先显示骨架/缓存，不能主线程假死。
- 连续浏览 10 页海报后返回首页不 OOM。
- 点播连续播放 30 分钟无明显音画不同步、播放器泄漏或持续内存上涨。
- 直播连续播放 60 分钟并至少切台 20 次，无恢复循环和 Surface 泄漏。
- 遥控器快速按键 50 次不崩溃、不产生多个重叠页面/播放器。
- 配置服务反复打开关闭 10 次，端口均能释放。

数值目标达不到时记录真实测量、瓶颈和优化前后对比，不删除测试。

## 7. Release 构建

- 签名参数只从 `local.properties`、Gradle 属性或环境变量读取。
- Debug 和 Release 使用相同功能配置，差异只能是日志、混淆、签名和可替换服务地址。
- Release 开启资源压缩/R8 前先保证 Debug 通过；再单独验证 Release 全流程。
- 版本码单调增加，版本名语义清晰；Android 4.4 变体使用独立更新清单，不能给主应用推错 APK。
- 生成 APK 后记录文件大小、SHA-256、包名、版本、min/target SDK 和签名证书摘要。

建议验证：

```powershell
.\gradlew.bat testDebugUnitTest lintRelease assembleRelease --console=plain
apksigner verify --print-certs app\build\outputs\apk\release\app-release.apk
apkanalyzer manifest min-sdk app\build\outputs\apk\release\app-release.apk
Get-FileHash app\build\outputs\apk\release\app-release.apk -Algorithm SHA256
```

## 8. 发布清单

- 已签名 APK。
- 对应 `update.json`。
- SHA-256、APK 字节数、版本号。
- 完整 CHANGELOG，单独说明 Android 4.4 已验证格式与硬件限制。
- API 19 实机验收记录和已知问题。
- 第三方服务配置说明，不包含密钥。
- 回滚版本和旧 APK 的可访问位置。

## 9. Gate 报告模板

```markdown
# Gate X 验收报告

## 目标

## 修改文件

## 自动化命令与原始结论

## 设备与环境

## 人工步骤及结果

## API 19 已验证

## 未验证/失败

## 风险与回滚

## 下一 Gate 是否允许开始
```

只有“下一 Gate 是否允许开始”为“是”且失败项不阻断主链路时，才进入后续阶段。
