## 上一版签名基线

原 APK：`https://github.com/ZxxXinI/tvbox-android4/releases/download/v0.0.1/app-release.apk`。

- 包名：com.tvbox.android44；versionName 0.0.1；versionCode 1；minSdk 19、targetSdk 28。
- 签名 DN：`C=US, O=Android, CN=Android Debug`。
- 证书 SHA-256：`d507b831ebd7af498c550d0e24b84d1a10f218132ec9e6ce4c43d19f15c1e2d6`。
- 当前云环境验证证书 SHA-256：`0e64f475052556db51387d103a43f11072afb5b676c03eeb7486737b90886e2a`，与原版不同。

证书摘要是公开校验信息，不是私钥。不能从 APK/证书恢复签名私钥，也不能生成一把不同的密钥后宣称可覆盖旧版。

用户已明确选择沿用原证书、保留覆盖升级，并上传原 keystore。实际别名 androiddebugkey、条目类型 PrivateKeyEntry，证书摘要与公开 v0.0.1 完全一致；原私钥问题已解决。本轮不更换证书。原证书本身是调试证书，发布材料如实标注 `legacy-debug-release`，不将其写成新的生产证书。

已核对当前工作区及默认用户目录中的 debug.keystore，其证书均为上述云环境摘要，与 v0.0.1 不同。原构建机器上的 `~/.android/debug.keystore` 是常见来源，但同名文件不能证明同一私钥，须核对摘要。口令放在未提交的 local.properties 或已有 GitHub Actions Secrets；云环境网络 Secret 不是本地 APK 签名凭据。

用户提供的私钥保存在仓库之外的受限目录，仅用于本地构建；没有提交到 Git、上传到 Release 或写入口令日志。构建启用 TVBOX_REQUIRE_RELEASE_SIGNING=true，使用受控签名配置和稳定 OTA 清单地址，实际签名摘要再次核对为原摘要。

## 已准备的可执行流程

业务源码提交：[454390141b5cae612368b4842877a7cfad89b903](https://github.com/ZxxXinI/tvbox-android4/commit/454390141b5cae612368b4842877a7cfad89b903)，已通过原生 Git 推送 main，远端引用核对一致。尚未创建 v0.0.2 标签。

首次在线验证：[GitHub Actions #1](https://github.com/ZxxXinI/tvbox-android4/actions/runs/37434928294)，公开页面显示 32 秒后 Failure、无 APK 产物；任务页要求登录查看日志。公开注释中的 Node.js 20 / setup-java v4 弃用和无产物警告不能据此判为失败根因，未凭猜测改依赖或把本地通过写成线上通过。API 恢复后先读取真实日志、修复并取得成功结果，再完成正式发布。

1. 在受控环境配置 TVBOX_STORE_FILE、TVBOX_STORE_PASSWORD、TVBOX_KEY_ALIAS、TVBOX_KEY_PASSWORD；私钥与口令不得提交或发送聊天。构建启用 TVBOX_REQUIRE_RELEASE_SIGNING=true。
2. 使用下面的稳定清单地址构建候选版本；版本码必须大于上一版。
3. 核对实际签名与上一版。发布工具增加 --previous-apk，默认拒绝版本码未递增和证书不一致；明确允许新证书迁移时才传 --allow-certificate-change，并在说明中记录无法覆盖升级。
4. 本轮以 --allow-legacy-debug-upgrade 显式沿用原调试证书；必须同时提供公开上一版 APK，版本码递增、两个 APK 的调试证书摘要完全相同，禁止同时允许证书迁移或启用 CI 验证模式。通过后从最终字节生成 APK、update.json、apk-info.json、signature.txt 和 SHA256SUMS，签名类别为 legacy-debug-release。
5. 在验证通过的源码提交上创建 v0.0.2 Release；先上传和重新下载验证 APK，再更新清单。发布完成后记录真实 Release URL、提交、证书、哈希和公开下载结果。

```bash
source /workspace/.cloud-setup/tvbox/env.sh
TVBOX_VERSION_NAME=0.0.2 TVBOX_VERSION_CODE=2 \
  TVBOX_REQUIRE_RELEASE_SIGNING=true \
  TVBOX_OTA_MANIFEST_URL=https://github.com/ZxxXinI/tvbox-android4/releases/latest/download/update.json \
  bash gradlew assembleRelease --no-daemon --max-workers=4 --console=plain

python3 scripts/prepare_release.py \
  --apk app/build/outputs/apk/release/app-release.apk \
  --previous-apk /workspace/.cloud-setup/tvbox/previous-release/app-release-v0.0.1.apk \
  --allow-legacy-debug-upgrade \
  --apk-url https://github.com/ZxxXinI/tvbox-android4/releases/download/v0.0.2/app-release.apk \
  --output-dir dist/release-validation \
  --changelog '播放、历史、AI、扫码与 OTA 流程补全'
```

本轮不得传 --allow-certificate-change。--allow-legacy-debug-upgrade 不接受另一张调试证书；实际 v0.0.2 云环境 APK 与公开 v0.0.1 比对后被正确拒绝，未生成输出目录或可上传的清单。13 项 Python 回归覆盖同证书历史调试签名、异证书、缺上一版、非递增版本、签名迁移/验证模式冲突及非调试证书误用。
