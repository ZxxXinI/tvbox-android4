# 03 工程架构与代码规则

## 1. 独立工程规则

建议源码目录为 `Android4.4/project/`，与主工程 `app/` 和 `tvbox_android6/` 隔离。独立维护：

- `settings.gradle`、根 `build.gradle`、Gradle Wrapper。
- `applicationId`、namespace、版本号和签名配置。
- 兼容依赖锁定文件。
- 独立 README、`AI_DEV_LOG.md` 和模块日志。

可以参考或复制纯领域算法，但不得通过 Gradle 依赖主工程模块，否则会把 Compose/Media3 和 API 28 边界带入。

## 3. 分层边界

### 3.1 UI 层

- 只负责渲染状态、收集用户事件、管理焦点和 Activity/Fragment 生命周期。
- 不直接拼 MacCMS 参数、不解析 `vod_play_url`、不读写 SharedPreferences。
- 不在 Adapter 中发起裸线程或持有 Activity 长引用。
- 播放器页面可以持有播放器实例，但换线决策和健康评分属于 domain。

### 3.2 Domain 层

- 使用普通 Java/Kotlin 数据类和纯函数，不依赖 Activity、View、OkHttp Response。
- 放置内容过滤、片名规范化、搜索去重、播放串解析、直播解析、缓冲判断和线路评分。
- 同一规则必须有单元测试，并可在 JVM 上运行。

### 3.3 Data 层

- DTO 与领域模型分离，转换时完成 trim、默认值、非法 URL 过滤和 HTML 清理。
- Repository 统一封装来源列表、超时、缓存、失败冷却和错误分类。
- SharedPreferences 只保存小型设置、历史和健康统计；海报和大响应交给图片/文件缓存。
- 外部接口的异常不得原样带 Key、Cookie、完整响应体进入用户日志。

## 4. 页面状态规则

每个页面状态至少包含：

- `loading`：是否正在首次加载。
- `refreshing` 或 `loadingMore`：不能与首次加载混为一谈。
- `data`：当前可用内容；后续请求失败时保留旧数据。
- `error`：面向用户的短消息和内部错误分类。
- `requestId`：忽略旧请求晚到结果。
- `focusedItemId`/`selectedId`：用于返回恢复。

状态更新必须发生在主线程；网络回调到达时先验证页面仍存活且 `requestId` 匹配。

## 5. 并发和取消规则

API 19 方案可用 `ExecutorService + Future/Call.cancel()`，也可使用已经验证兼容的协程版本；无论方案如何，都必须满足：

- 搜索/补线全局并发上限 3。
- 离开页面、发起新搜索、切换接口时取消旧请求。
- 取消不计入来源失败，不触发冷却。
- 单来源超时不取消其他来源。
- 所有回调在页面销毁后不得操作 View。
- Executor、Handler 回调、播放器监听和局域网 ServerSocket 必须显式关闭。

## 6. 统一结果和错误分类

建议统一结果类型：

```text
Result<T>
  Success(data, source, fromCache)
  Failure(kind, userMessage, cause)
  Cancelled
```

错误 `kind` 至少包括：

- `NO_NETWORK`
- `DNS`
- `TLS`
- `TIMEOUT`
- `HTTP`
- `EMPTY_BODY`
- `PARSE`
- `UNSUPPORTED_DEVICE`
- `PLAYBACK`
- `PERMISSION`
- `CANCELLED`

用户只看可操作中文提示；开发日志记录来源 ID、错误分类、HTTP 状态和耗时，不记录密钥与完整 URL 查询参数。

## 7. 配置注入规则

- AI 默认 Key、平台直播服务地址、更新清单地址、直播源地址、签名信息均从 `local.properties`、Gradle 属性或环境变量注入。
- 公开仓库只保留空值或无敏感信息的示例文件。
- 运行时自定义配置统一经 `SettingsRepository` 保存。
- URL 保存前必须 trim、补全 MacCMS 末尾 `/`、限制 `http/https`，拒绝 `file:`、`javascript:` 等 scheme。
- 包内默认来源是只读列表；用户自定义来源与内置来源分开保存，可删除自定义项但不能覆盖内置定义。

## 8. 生命周期规则

- Activity/Fragment `onStop` 时暂停普通点播；直播是否继续由明确产品规则决定，首版统一暂停。
- `onDestroyView` 清空 Adapter 对 View 的引用并取消页面任务。
- 播放器进入时获取音频焦点，离开时释放；处理耳机/HDMI 音频变化和 Audio becoming noisy。
- 配置 HTTP 服务只在配置对话框存在期间运行。
- OTA 下载在首版不要求后台跨进程续传；页面销毁必须给出明确取消行为。

## 9. 代码质量规则

- 单个类优先不超过 500 行；页面事件、Adapter、Repository 和 Parser 分文件。
- 禁止 `catch (Exception) {}` 空吞；至少分类并记录不敏感摘要。
- 禁止用静态 Activity/Context 解决生命周期问题。
- 禁止在 Adapter 的 `onBindViewHolder` 重复创建播放器、HTTP 客户端或线程池。
- 禁止把外部 DTO 直接传到 UI。
- 常量集中：并发、超时、缓存 TTL、最大条目、缓冲阈值不得散落。
- 所有新增解析规则至少包含正常、空值、畸形、重复和中文输入测试。

## 10. 与主工程的映射

| 主工程 | Android 4.4 对应实现 |
| --- | --- |
| `TvBoxViewModel.kt` | 页面 Controller/Presenter + Repository，按 feature 拆分 |
| Compose `TvBoxApp.kt` | Activity/Fragment 导航容器 + XML Views |
| Compose Screen | Fragment/Activity + RecyclerView Adapter |
| Media3 `PlayerScreen.kt` | ExoPlayer 2 `PlayerView` + 独立播放器控制器 |
| kotlinx.serialization DTO | Gson DTO + 显式转换 |
| 协程 Flow 增量结果 | 线程池/Call 回调 + requestId + 主线程增量合并 |
| Compose focus | `nextFocus*`、`OnFocusChangeListener`、焦点恢复器 |
