# 06 点播、搜索、详情与历史规则

> 当前实现以 [13-当前版本基线与验收清单.md](13-当前版本基线与验收清单.md) 为准：首页为当前 MacCMS 视频源；直播入口暂时隐藏。文中上游 v1.3.6 信息仅作为历史设计参考。

## 1. 首页加载

1. 读取已保存的视频接口、主题与字体，展示当前 MacCMS 来源首页。
2. `ac=list&pg=1` 分类表与 `ac=detail&pg=1` 内容独立加载；分类失败只提示，不阻断内容。
3. 根级“全部”不传分类 ID；子分类传自己的 ID；父分类“全部”聚合其子分类，去重影片并保留成功子页。
4. 滚动接近底部才加载下一页；同页请求只有一个。页码仅在成功后递增，失败可重试。
5. Activity 重建后恢复来源、分类、已加载页数、滚动与卡片焦点；保存状态不打包整批影片。
6. 新接口取消旧请求并重载；页面销毁后不能继续更新旧 View；历史不清空。

## 2. 视频源卡片到播放详情

```text
当前视频源卡片（apiLineId + movieId）
  → 该来源 ids 详情
  → 立即显示主详情、线路和选集
  → 后台按片名及年份补充替代来源线路
  → 播放已有线路
```

首页不加载豆瓣，不要求豆瓣映射到资源站。保留的 Douban 类仅为历史代码，不属于当前用户流程。

## 3. 多来源搜索调度

- 搜索词 trim 后不能为空；新搜索增加 `requestId` 并取消上一搜索。
- 来源顺序：当前主来源固定第一；其余来源排除冷却项后按近期成功和延迟排序。
- 首页、搜索和详情补线共用视频源请求上限 3；单来源搜索预算 3 秒，排队包含在预算内。分类子请求使用单独受管理线程池，避免父任务占满同一线程池。
- 每个来源完成后，在主线程增量合并结果并更新 `已完成 N/M 条线路 · 找到 X 个结果`。
- 单来源失败只增加已完成数和健康记录，不把整页置为错误。
- 所有来源完成且结果为空，才显示统一空态。
- 用户离开页面导致的取消不计失败、不显示错误。

## 4. 去重与展示

- 去重键使用规范化片名 + 年份。
- 相同作品保留主来源卡片；主来源较晚返回时在原位置更新元数据与点击目标；稳定卡片 ID 为规范化片名加年份。记录 `availableSourceIds` 供详情补线。
- 首次出现顺序保持稳定，后续增量结果不得重新洗牌导致焦点跳动。
- 海报为空显示占位；海报失败不影响卡片点击。
- 搜索结果经过统一内容过滤。

## 5. 详情渐进补线

1. 先请求用户点击卡片所属来源的 `ids` 详情。
2. 主详情返回后立即渲染元信息、主线路和选集。
3. 其他来源以片名搜索候选，再请求最匹配候选详情。
4. 替代来源最多三条并发，单来源完整匹配流程超时 4 秒。
5. 每发现有效线路立即追加，不等待全部来源。
6. 按稳定 `lineId` 去重，追加时不能重置当前线路、选集或焦点。
7. 慢源/失败源进入 2 分钟冷却；取消不进入冷却。

详情状态必须区分：主详情加载、补线进行中、已有线路数量、完成来源数量和单独补线错误。已有可播放线路时，补线失败不得覆盖详情页为全屏错误。

## 6. 线路与选集

- 默认优先名称含 `m3u8` 且有有效选集的线路，否则选择第一个有选集线路。
- 线路按钮显示来源名和线路名，必要时显示“推荐/近期失败/较慢”。
- 切换线路时，优先按当前集标题匹配新线路；无法匹配时限制到合法索引并提示。
- 大量剧集使用 RecyclerView 网格，稳定 ID 为 `lineId + episodeIndex + title`。
- 进入详情默认聚焦“继续播放”或当前线路的历史集数；无历史则第一集。
- 补线追加后不改变用户已经选择的线路。

## 7. 历史记录

保存字段：影片 ID、来源 ID/名称、影片名、海报、类型、备注、线路索引/名称、集索引/标题/URL、进度、总时长、更新时间。

规则：

- 同一 `apiLineId + movieId` 覆盖旧记录，按更新时间倒序；读取和写入都返回/保存独立快照。
- 最大 100 条，超出删除最旧记录。后台磁盘队列顺序保存；临时文件同步并原子替换，失败保留原文件和缓存，不通知成功。损坏 JSON 备份为 `.corrupt`，无效单条记录丢弃。
- 播放 READY 后开始节流保存；每 10 至 15 秒、暂停、切集、换线和退出时保存。
- 进度百分比仅在时长与位置均有效时计算，并限制 0 至 100。
- 片尾自然播放完成时可把当前集标为完成；进入下一集后保存新集状态。
- 历史页读取时再次执行内容过滤，损坏条目单独丢弃。
- 清空历史有二次确认，完成后焦点回到空态返回按钮。

## 8. 历史恢复

恢复顺序：

1. 根据历史的来源 ID 和影片 ID 重新取详情。
2. 找到同名线路和同标题集；索引只作为第二选择。
3. 使用最新地址创建播放器。
4. 仅在重新获取失败且历史 URL 仍是合法 `http/https` 时，提示用户并允许临时尝试旧地址。
5. 进度距离片尾过近时从头或下一集开始，具体阈值集中定义。

## 9. 空态与错误文案

- 首页失败：“内容加载失败，请检查网络或切换视频接口。”
- 搜索为空：“没有找到相关影片，可以换个关键词或视频接口。”
- 主详情失败：“影片详情加载失败，请重试或返回搜索结果。”
- 补线失败但有主线路：“其他线路暂未加载完成，当前线路仍可播放。”
- 历史失效：“原播放线路可能已更新，正在重新查找资源。”

不得把域名、Key、堆栈或完整异常显示给普通用户。

## 10. 单元测试最低集合

- 播放串中 `$$$`、`#`、`$` 的正常/错位/空值/Markdown URL。
- HTML 清理与实体替换。
- 片名规范化不误合并不同季。
- 多来源增量合并、主来源优先和稳定顺序。
- 并发上限 3、3 秒超时、取消不记失败。
- 详情追加线路不重置选择。
- 历史覆盖、排序、上限、损坏 JSON 回退和进度计算。

## 当前流程实现补充（2026-10-06）

- 历史入口传递记录快照；普通详情后台读取历史，UI 不等待磁盘；首次详情失败可确认合法旧地址并保留原影片/集数。
- 详情和播放器共用 PlaybackSelection：线路 ID → 名称 → 默认可播放线路，集标题优先、合法索引兜底。接近片尾时下一集从 0 开始，最后一集从头；返回详情和状态重建不重复跳集。
- 播放器结果直接返回当前线路/集/进度，统一 REQUEST_PLAYBACK；详情更新继续播放并恢复当前集焦点，保存尚在排队也可正确返回。
- 选集稳定 ID 包含线路、集索引和标题；线路追加和选择变化使用差异更新，不整表重置。
- 自动化证据见 PlaybackSelectionTest、PlayerFlowTest 与验证报告；真实播放和遥控器结果仍填入 `13`。
