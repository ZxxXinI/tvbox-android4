# 02 Android 4.4 兼容性与技术选型规则

> 当前实现以 [13-当前版本基线与验收清单.md](13-当前版本基线与验收清单.md) 为准：首页为当前 MacCMS 视频源；直播入口暂时隐藏。文中上游 v1.3.6 信息仅作为历史设计参考。

> 2026-10-07 用户授权扩展至 Android 4.1 / API 16。下表为新的当前边界；历史 API 19 验收仍保留。详细证据见 [兼容扩展](17-Android4.1兼容扩展.md)。

## 1. 核心判断

Android 4.4 兼容不是把主工程的 `minSdk=28` 改成 19。当前主工程使用 Compose、Compose for TV 和 Media3，这些依赖不能作为 API 19 实现基础。新工程必须保留产品行为，重建 UI 和播放器适配层。

## 2. 固定构建边界

| 项目 | 规则 |
| --- | --- |
| 最低系统 | `minSdk = 16`，Android 4.1 |
| 编译 SDK | 建议 35；可随本机构建环境调整，但不得因此提高 `minSdk` |
| 目标 SDK | 首个侧载版建议 28；如需应用商店，建立单独现代发行变体并处理新权限/存储规则 |
| 构建 JVM | JDK 17 运行 Gradle/AGP |
| 应用字节码 | Java 8 语法级别，避免依赖新 Java 运行时 API |
| UI | XML、Activity/Fragment、自定义 View、RecyclerView |
| 包名 | 独立包名，例如 `com.tvbox.android44` |
| ABI | 首版不引入自有 native 库；如后续引入，至少核对 `armeabi-v7a` |

建议使用 Groovy 或 Kotlin DSL 均可，但所有依赖必须集中管理并锁定版本。不得写 `+`、`latest.release` 或动态 BOM。

## 3. 建议依赖基线

以下版本用于建立第一个可构建基线，升级前必须验证 AAR Manifest 的 `minSdk`、依赖树和 API 19 实机：

| 能力 | 建议依赖 | 备注 |
| --- | --- | --- |
| Activity/主题 | `androidx.appcompat:appcompat:1.6.1` | 传统 Views，不用 Compose |
| 列表 | `androidx.recyclerview:recyclerview:1.3.0` | 海报网格、频道和选集 |
| 布局 | `androidx.constraintlayout:constraintlayout:2.1.4` | 可选；简单页优先原生布局 |
| 播放器 | `com.google.android.exoplayer:exoplayer-core:2.19.1`、`exoplayer-hls:2.19.1`、`exoplayer-ui:2.19.1` | 旧包已停止演进，但其官方构建常量为 `minSdk=16` |
| HTTP | `com.squareup.okhttp3:okhttp:3.12.13` | 兼容旧 Android 的冻结分支；禁止混入 OkHttp 4/5 |
| REST | `com.squareup.retrofit2:retrofit:2.9.0`、`converter-gson:2.9.0` | 也可直接 OkHttp，避免重复网络栈 |
| JSON | `com.google.code.gson:gson:2.10.1` | 所有字段容忍缺失和未知字段 |
| 图片 | `com.github.bumptech.glide:glide:4.16.0` | 必须限制缓存和并发；若依赖冲突则降级到已验证版本 |
| 二维码 | `com.google.zxing:core:3.3.3` | 避免新版初始化引用 API 19 StandardCharsets；仅生成二维码 |
| 测试 | `junit:junit:4.13.2` | 纯逻辑测试 |

依赖版本不是“越新越好”。一旦某版本把最低 API 提高到 21/23，必须保持已验证旧版本或替换组件，不得伪造兼容。

## 4. 明确禁止的技术

- `androidx.compose.*`、`androidx.tv.*` Compose 组件。
- 当前 `androidx.media3`。当前官方支持矩阵已把核心视频/HLS 支持起点提高到 Android 6.0 / API 23。
- 仅支持 API 21+ 的最新 AndroidX 版本。
- `java.time`、`java.nio.file`、`CompletableFuture` 等没有明确 desugaring/回退的运行时调用。
- 无版本判断的 `JobScheduler`、`NetworkCapabilities`、通知渠道、画中画、`PackageInstaller.Session` 等高版本 API。
- 依赖 WebView 新特性承担核心播放。
- 为通过构建而使用 `tools:overrideLibrary`。

## 5. 可选 Leanback 策略

官方旧版 `com.android.support:leanback-v17:28.0.0` 的文档最低为 API 17，但它属于停更 Support Library。新工程默认使用可控的 RecyclerView + 自定义焦点，不同时混用 `android.support.*` 与 `androidx.*`。

如果确实使用 Leanback，必须二选一：

- 全工程采用旧 Support Library 28.0.0，并验证与播放器/图片库的依赖兼容；或
- 采用已验证 `minSdk <= 19` 的早期 AndroidX Leanback 版本。

不得只为减少 UI 代码而引入一套与现有 AndroidX 冲突的旧支持库。

## 6. Manifest 兼容规则

必须声明：

- `INTERNET`、`ACCESS_NETWORK_STATE`。
- 语音功能启用时声明 `RECORD_AUDIO`；API 19 不需要运行时权限弹窗，API 23+ 必须动态请求。
- OTA 使用 `FileProvider` 分享 APK，不使用 `file://` URI。
- `android.software.leanback` 为 `required=false`。
- `android.hardware.touchscreen` 为 `required=false`。
- Activity 保持横屏并处理常见键盘、导航和屏幕尺寸变化。

兼容分支：

- `<queries>` 只在 Android 11 包可见性场景有意义，不能依赖它解决 API 19 语音服务查询。
- `REQUEST_INSTALL_PACKAGES` 和 `canRequestPackageInstalls()` 仅在 API 26+ 分支使用；API 19 调系统安装器。
- `usesCleartextTraffic` 在旧系统不生效，但在新系统仍需按源地址策略配置。
- API 24+ 使用 `FileProvider` URI；为统一和安全，所有版本都走 `FileProvider`。

## 7. TLS 与网络兼容规则

Android 4.4 的 TLS、证书根和密码套件可能无法访问现代 HTTPS 服务。必须：

- 使用真实 API 19 设备分别验证 MacCMS、豆瓣、AI、OTA 和图片域名。
- 区分 DNS、握手、证书、HTTP 状态、超时和 JSON 解析错误。
- 允许服务端提供受控的 HTTPS 兼容代理，但不得在客户端关闭证书校验。
- 对仍为 HTTP 的授权源只做精确配置，不提供“信任任意地址”的安全开关。
- 请求统一设置 User-Agent、连接/读取超时，并限制重试次数。
- 不把 HTTPS 失败静默改成 HTTP。

## 8. 媒体兼容边界

- 首版正式支持目标：H.264 AVC、AAC-LC、普通 MP4、未加密 HLS/m3u8。
- H.265、10-bit、4K、HDR、AV1、杜比、DTS、加密 HLS 和 DRM 必须标为“设备相关/未承诺”。
- 优先硬解；解码器初始化失败时显示具体格式和设备限制，不无限重试。
- 播放实测必须覆盖至少一个 HLS 和一个 MP4，且有声音、画面、进度和返回恢复。
- 模拟器结果不能替代真实盒子，官方也建议媒体兼容尽量使用物理设备验证。

## 9. 低配置设备性能预算

- 首屏不同时请求海报原图；列表图按显示尺寸下采样。
- 影视接口同时在途最多 3 条；图片并发建议 2 至 4 条。
- 只保留当前页和邻近页数据，避免无限列表常驻大图 Bitmap。
- 离开播放器立即释放 `SimpleExoPlayer`、Surface、监听器和定时任务。
- 避免大 JSON 在主线程解析，避免一次性持有直播源原文与所有转换副本。
- Debug 版开启 StrictMode 辅助发现主线程网络和磁盘访问。
